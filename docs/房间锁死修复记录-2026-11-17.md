## 根因（三层，全部有反汇编/日志实证）

### 1. op 87 房间条目线格式错误（注册失败的真正根因）
客户端解析链（全部亲自反汇编核对）：
- `0x50FF27`：E2(房数) → 每房 E4(blobLen) + blob（3度加密）
- `0x78E2F0/0x78C120`：解密后要求 blob[0]==0x18，读 E4(payloadLen)，**强制 blobLen == payloadLen+5**
- `0x78BE30 (Decode2) → 房号`（0x505123 的查找键！）、`0x78BE60 (Decode4) → 会话句柄`
- `0x504E9B`：Str(房名) → B(+0x48) B(+0x54) B(+0x6C) W(+0x78) B(+0x84) B(+0x90) B(+0x9C) B(+0x20) B(+0x60) E4(+0xC0 会话索引) B(+0xA8) → [闸门 0x6C054E(0x43) 成立再读 B(+0xB4)]

旧 AI 版的错误：把 rd 房号 61(0x3D) 当"未知字段"、把句柄 119 错当房号、发明了不存在的"0x00 ssd 类型字节" → 我方条目被客户端注册成 **61 号房**，而 op 83 找 **75 号房** → 永远找不到 → 注册断链 → 一切降级。
**修正后对账**：练习房条目（空名）= 31B、rd 条目 = 33B，与上游笔记记录的官方 blobLen 两笔完全一致。

### 2. op 84 无人应答 + 新舞台无数据
进房 30 tick 注册检查失败 → 客户端发 C→S op 84 并把 [stage+0x2F78] 置 4 → UI 全灰。
- 上游/作者/AI 三版 recv 表都没有 op 84 → 日志 `[UNKNOWN] 84`
- 收到 S→C 84 成功分支后客户端会**重切房间舞台**，新舞台数据全空 —— 不补链就出现"假人消失/选图灰/点击无包"（上游 RoomEntryChain 的 backToRoom 注释同源）

### 3. 房间舞台的锁只能由客户端自己清
S→C 84 清的是大厅等待锁；房间舞台的锁在 op 84 发送函数 0x51F8FC 内部
（`0x51FB50: mov [esi+0x2F78],4` + `0x51FB5A: call [eax+0x1C4]` 禁用 UI）设置。

## 追加修复（2026-11-17 深夜）：激战 NPC 不动/不死

### 现象
激战模式的 4 个默认 NPC（歪仔/阿八/害宝/嘿木）进对局后原地不动、打不死、不掉道具；
但手动换角色、调等级、或踢出再请回之后，被操作的 NPC 就正常了。

### 根因（反汇编 CA.exe 0x52B39A 钉死）
客户端的 op 103 处理器只是**更新器**：0x6861C8 查 AI 实体指针数组
（ctx+0x1E4+槽位*0xC），实体不存在时只写难度+刷 UI，**不创建实体**。
进房链里的 op 103 到达时，客户端激战策略（CPrepareStrategyAIBattle）的
每槽上下文尚未就绪 → 配置丢失 → 对局 NPC 是空壳。
之后任何**客户端主动触发**的 op 103（换人/调等级/踢出再请回，即 op 88/89）
都发生在策略就绪后 → 有效。这就是"操作过就正常"的原因。

### 修复
1. **op 92（点"开始"）瞬间补发 NPC 实体断言**：StartGameReq 收到后、发开局数据前，
   按 op 88 成功路径同形补发全部 NPC 的 [SlotBomber(105) + PracticeSlot103(refSlot=房主位)]。
   与"手动调完再开始"的成功时序完全一致，与进房时机解耦。每房间代幂等（Room.currentGeneration）。
2. **op 156（NpcEventReq，NPC 房间定时器）首包同样触发断言**（进房后 ~2 秒内的早期信号）。
3. 进房链 op 103 的 refSlot 保持指向房主位（0）——AI 槽自身没有玩家信息。

### 验证
日志：op 92 → [NpcAssert] 补发 [105+103]×4 → activeSlots=[0,4,5,6,7] AI=4 → 实测 NPC 正常行动/可击杀。
