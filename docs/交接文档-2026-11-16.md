## 2. 逆向结论（最有价值的知识沉淀，按可信度排序）

### 2.1 「按钮全灰」的真正根因链（已钉死，CA.exe 汇编级验证）

```
建房链发 RoomList(emptyList())
  → 客户端房间缓存数组（lobby+0x6968，每条 0xCC，由 op 87 填充）为空
  → op 83 SessionSimpleInfo（内含房号 75）处理器 0x506513 用 0x505123 按房号查缓存，
    找不到 → “整段跳过”
  → 玩家注册断链
  → checkA（0x68848D：槽位 3B meta[0] 须含 bit0x2 “在线”标志）= 0
  → 进房 30 tick 后 0x521B89 自动发 C→S op 84 并把 [stage+0x2F78] 置 4 → UI 全锁
     （选角/换图/开始/商城全灰）
```
官方正确路径：`checkA≠0 && checkB==0` → 直接调 0x51CAAD 恢复 UI，**根本不发 op 84**。所以日志里出现 `SessionDetailInfoReq (84)` 就是“注册断链”的判据。

> **⚠️ 本轮更正（重要）**：本轮进一步发现，仅补 op 87 条目还不够——旧 fork 在 mode 14/15 只下发 slot 0，其余 7 槽整段缺失，checkB（各槽须有玩家信息）仍不满足。**官方 tst.pcap 练习房 = 1 真人 + 7 电脑（8 槽全部初始化）**。所以修复必须是“8 槽全下发 114/104/105 + 槽 1..7 补 103”，见 `LocalRoomEntry.kt`。

### 2.2 op 87 RoomList 真实线格式（完整逆向 0x50FF27→0x78E2F0→0x78C120→0x78BB60→0x504E9B）

```
E2(房数) + 每房 [ E4(blobLen) + blob(整体 3 度加密) ]
blob = 0x18 标记 + E4(payloadLen)        // blobLen = payloadLen + 5
     + 0x00(ssd 类型字节)
     + stream:
         W(未知, rd 抓包=0x003D)
         E4(房号, 低 16 位=缓存下标)
         Str(E4 长度 + 房名)
         B(+0x48) B(+0x54) B(+0x6C)
         W(+0x78)
         B(+0x84) B(+0x90) B(+0x9C)
         B(容器+0x20) B(容器+0x60)
         E4(会话索引 → 容器+0xC0)
         B(+0xA8)
         [+B(+0xB4) 仅当闸门 0x6C054E(0x43) 成立]   // 服务端恒补一个 0x00 兼容两种情况
```
- 加密：`Encrypt1 = n^0x5A`、`Encrypt2 = writeShort(n^0xA569)`、`Encrypt4 = writeInt(n^0x96CA5395)`；blob 内容是“3 度加密”（4B LE 读 ^0x96CA5395 按 BE 写回；余 2B ^0xA569；余 1B ^0x5A）。实现见 `RoomList.kt` 的 `cipher3/decipher3`。
- 旧实现是对 rd 抓包的误读（f1=33 实为 blobLen、f2=0x1C18 实为 0x18 标记、f4=119 实为房号），线字节恰好对齐但语义错位且从不下发条目。
- 房号 75 必须与 op 83 硬编码一致；会话索引 0（< op 72 会话列表数，单用户=1）。

### 2.3 op 84 / op 77 语义（本轮推翻了之前的错误结论）

**推翻**：之前以为 C→S op 84 是“会话详情请求”、应答是 S→C op 391 SessionDetailInfo。**这是错的**：按上游 EN_18 协议表，C→S op 84 = `StartGameResultReq`，S→C op 84 = `JoinFreeSessionResult`；**op 391 在本协议里根本没有对应实现**，此前那个 `SessionDetailInfo` 应答会让客户端弹框+离房，**已从源码中删除**。

**新结论（已用 CA.exe 反汇编验证）**：
- **C→S op 77 = `JoinFreeSessionReq`（快速加入 / 激战模式入口）**。CA.exe `sub_50D4DC` 发包点 0x50EDD9 / 0x5144F9 / 0x5EDAD7 / 0x6B14EA。**旧 fork 的 recv 表没有 op 77（日志显示 `[UNKNOWN] 77`）→ 客户端点了完全没反应，这就是“激战模式完全开不了”的根因。**
  - 请求结构：`E1(本地玩家数) + N×E1(角色 id) + E2(filter1) + E2(filter2)`；实测 body `5B 5C A5 0D A5 69` = `E1(1) E1(6) E2(100) E2(0)`（E1 值经过 ^0x5A 加密）。
- **S→C op 84 = `JoinFreeSessionResult`**。客户端 `CLobbyStage::OnPacket 0x510287 case 'T'(0x54) → sub_507CC7`：先清 op 77 等待锁，再 `switch(Decode1 result)`：
  - `case 0` 成功：`E2(房号) + E4(序号) + E1(房型) + E1(状态)`，写入 CFxContext（0x68739E/0x68626F/0x687393），0x505123 按房号到 op 87 缓存找房 → 切房间舞台。
  - `case 2..12` 失败：只弹对话框，不再读字段。**没有 case 1**。
  - 错误码：2 CantFindEmptyRoom / 3 InvalidGrade / 4 InvalidLucci / 6 DontHaveTMItemJoin / 7 UserRejectJoinSession / 8 InvalidLevel …
  - 与 op 83 的区别：83 是“进指定房”（case 1 = WrongPassword，字段 `E1+E1+E2+E1+E1`），84 是“自动找房”（字段 `E1+E2+E4+E1+E1`）。

**离线单机策略**：op 77 没有别的玩家可匹配 → 直接当“创建本地 AI 激战房（mode 16）”，回 `result=0 + 房号 75`，再下发整套房间初始化链。

### 2.4 房间初始化线序（以官方 tst.pcap stream4 为准）

```
[87 RoomList, 83 EnterSessionResult, 4(13B), 4(65B), 113, 100(78B), 108,
 106×8, 每槽(114, 104, 105) + 下一槽的 103 (槽 7 无 103), 198(持有物), 423]
```
- 8 槽必须全部下发 114/104/105，槽 1..7 还要 op 103（PracticeSetSlotAI），否则 checkB 不满足 → 30 tick 后自动 op 84 锁 UI。
- **op 103 字段语义**：`E2(slotIdx) + E1Bool(isAI) + E2(refSlot) + E2(aiLevel)`。第 3 栏 refSlot 必须 0..7（客户端 0x52B3E8 校验，抓包=槽号），第 4 栏才是难度 0..4。
  - ⚠️ 本项目 `PracticeSlot103` 参数名错位：其 `aiLevel` 形参实际落在 refSlot 栏，`flag` 形参才是难度。调用须传 `PracticeSlot103(slot, isAI, aiLevel = slot, flag = 难度)`。这是本轮修正的关键点之一。
- op 88 `AILevelChangeReq` 里旧的“mode 14/15 只发 slot 0、关掉 103”的 hack 已移除。
