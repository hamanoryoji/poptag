泡泡堂（PopTag / BnB）2010 美服 EN 客户端的本地离线服务端，基于开源项目 **BnbEmu** 修改，使其可以在**本机脱离官方服务器独立开局游玩**。

## 项目背景

BnbEmu 是社区对泡泡堂私服协议的逆向实现（Kotlin / Netty）。上游实现聚焦大厅、聊天、房间创建等基础链路，但**房间内"选角色 / 选地图 / 开始游戏 / 商店"四个按钮长期处于灰色不可点状态**，且**怪物模式、激战模式无法开局**。

本仓库记录并修复了这些问题的完整根因，根因全部通过 `CA.exe` 反汇编 + 抓包逐字节对账确认。

## 核心修复：房间锁死（UI 全灰）

### 症状

进入房间后：
- 「选择角色」「选择地图」「开始游戏」「商店」按钮全部灰色，点不动
- 客户端日志中每帧上报 `[UNKNOWN] 84`
- 严重时房间假人消失、点击无任何包发出

### 根因（三层）

**第 1 层：op 87 房间列表条目线格式错误 → 注册断链**

客户端解析链（`0x50FF27` → `0x78E2F0` → `0x78C120` → `0x78BE30` → `0x504E9B`）：

```
E2(房数) + 每房[ E4(blobLen) + blob(3 度加密) ]
blob = 0x18 标记 + E4(payloadLen)   // 强制 blobLen == payloadLen + 5
     + W(房号) + E4(会话句柄)
     + Str(E4 长度 + 房名)
     + B(+0x48) B(+0x54) B(+0x6C) W(+0x78)
     + B(+0x84) B(+0x90) B(+0x9C) B(+0x20) B(+0x60)
     + E4(+0xC0 会话索引) B(+0xA8)
     [+ B(+0xB4) 仅当闸门 0x6C054E(0x43) 成立]
```

旧实现把抓包里的 `0x3D`（房号 61）当成"未知字段"、把 `119`（会话句柄）错当成房号，导致服务端下发的房间条目被客户端注册成 **61 号房**，而 `op 83` 找的是 **75 号房** → `0x505123` 查房间缓存永远失败 → **整段跳过** → 玩家注册断链。

**第 2 层：op 84 无人应答 + 新舞台数据全空**

注册检查（进房 30 tick 后由 `0x521B89` 触发）失败 → 客户端自动发 `C→S op 84`，并把 `[stage+0x2F78]` 置 `4` 锁死 UI。三版服务端（上游 / 作者 / 早期 AI 版）的 recv 表都没有 op 84，日志表现为 `[UNKNOWN] 84`。

即使补了应答，S→C 84 成功分支会让客户端**重切房间舞台**，新舞台数据全空 → 必须紧接着**重发整套进房链**，否则出现"假人消失 / 选图灰 / 点击无包"。

**第 3 层：房间舞台的锁只能由客户端自己清**

S→C 84 清的是**大厅**等待锁；**房间舞台**的锁写在 op 84 发包函数 `0x51F8FC` 内部：

```asm
0x51FB50: mov [esi+0x2F78], 4      ; 置锁
0x51FB5A: call [eax+0x1C4]         ; 禁用 UI
```

### 修复

| 层 | 手段 | 位置 |
|---|---|---|
| 线格式 | stream 首字段改为 `W(房号) + E4(句柄)`，删除误加的 `0x00` 类型字节 | `server/src/main/kotlin/bnbemu/packet/RoomList.kt` |
| 应答 + 补链 | 新增 `SessionDetailReq`（recv 84）→ 回 S→C 84 并重发整链 | `handler/SessionDetailReq.kt` + `server/LocalRoomEntry.kt` |
| 客户端防锁 | 17 字节外科补丁，NOP 掉上面三条置锁指令 | 见 `docs/`（不随仓库分发二进制） |

**对账结果**：修正后练习房条目（空名）= **31 B**、rd 条目 = **33 B**，与上游抓包笔记记录的官方 `blobLen` 两笔完全吻合。

## 其他修复

- **激战模式开不了**：`C→S op 77 = JoinFreeSessionReq` 缺 handler（日志 `[UNKNOWN] 77`）→ 补 `handler/JoinFreeSessionReq.kt` + `packet/JoinFreeSessionResult.kt`（S→C 84）
- **怪物模式 NPC 不动 / 打不死 / 不掉道具**：补齐 NPC 行为与掉落判定
- 房间模型恢复作者原版（怪物/练习单人、激战槽 4..7 四个 NPC）

## 构建

需要 **JDK 17+** 与 **Maven 3.8+**。

```bash
cd server
mvn -q test                # 跑回归测试（225+ 项）
mvn -q -DskipTests package # 产出可部署 jar
```

产物在 `server/target/`。

## 运行

1. 准备一份合法持有的 PopTag 2010 EN 客户端
2. 将 `server/target/classes` 与两份 `EN_18_*.yaml` 放到服务端目录
3. 启动服务端（默认监听 `3838`），客户端连接本地地址
4. 账号数据存放于 `server/data/`（已被 `.gitignore` 排除）

## 协议要点备忘

| 编码 | 规则 |
|---|---|
| `Encrypt1` | `n ^ 0x5A` |
| `Encrypt2` | `n ^ 0xA569` |
| `Encrypt4` | `n ^ 0x96CA5395` |
| 字符串 / Blob | 3 度变换：4B 小端读 ^ `0x96CA5395` 按大端写回；余 2B ^ `0xA569`；余 1B ^ `0x5A` |

| opcode | 方向 | 含义 |
|---|---|---|
| 87 | S→C | RoomList（房间列表，填充客户端房间缓存） |
| 83 | S→C | SessionSimpleInfo（进指定房应答，含房号） |
| 84 | C→S | SessionDetailReq（注册失败兜底请求） |
| 84 | S→C | JoinFreeSessionResult（快速加入结果） |
| 77 | C→S | JoinFreeSessionReq（快速加入 / 激战入口） |
| 100/103/104/105/106/114 | S→C | 练习房槽位链 |
